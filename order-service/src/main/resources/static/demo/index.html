Why the failure path is the interesting one

When payment is declined, stock has already been reserved in another service and another database. There is no transaction to roll back, so the order service must explicitly undo it: it emits ReleaseInventory and holds the order at COMPENSATING until inventory confirms. Only then does it become CANCELLED. If the process died in that window, the database would still show the truth — stock is held — rather than a cancelled order with inventory silently stranded against it.
